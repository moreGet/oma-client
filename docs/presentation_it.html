→

tool 메시지 재요청 ↺
  • › SSE 이벤트: message_start · content_delta{delta} · tool_call{id,name,arguments} · message_stop{stop_reason,usage} · error
  • › stop_reason == tool_use → 클라가 도구 실행 후 tool 메시지로 재요청(루프 지속). end_turn → 종료

  • › max_tokens는 서버 제어 — 클라 설정 제거, 와이어엔 상수(DefaultMaxTokens=4096)만 전송
보안 모델 ①

멀티루트 샌드박스

IWorkspaceContext가 모든 파일/셸 경로를 활성 루트 기준으로 검증.

  • ✓ 최대 10개 루트 동시 등록 + 폴더별 Enabled 토글(전역 설정, 프로젝트 비귀속)
  • ✓ ResolvePath: 상대→주 루트 Combine, 검증은 활성 루트 OR(하나라도 내부면 통과)
  • ✓ 심볼릭/실경로 정규화 후 비교로 ..·절대경로 탈출 차단
  • ✓ run_command cwd = 주 루트. 시스템 프롬프트에 Roots 전체 고지

보안 모델 ② · 도구 시스템

ITool + 권한 게이트

20개 도구, 공통 ITool 계약. ToolRegistry가 서버용 스키마 생성.

  • ✓ ToolRisk: ReadOnly · Write · Execute · Destructive
  • ✓ IPermissionService = 위험도 × PermissionMode(Manual/AutoSafe/FullAuto)로 승인 결정
  • ✓ ReadOnly는 항상 자동, Destructive/Execute는 Manual·AutoSafe에서 승인 카드
  • ✓ run_command는 SecurityValidator 블랙리스트로 위험 명령 차단(FullAuto에서도 적용)

서버 연동 · API 계약

stateless HTTP + SSE

MethodPath용도
POST/api/v1/auth/login로그인 → JWT
GET/api/v1/health헬스 체크 (Public)
GET/api/v1/models활성 Provider 모델 목록
POST/api/v1/agent/chat에이전트 루프 — messages + 도구 스키마 → SSE
GET/api/v1/users/me프로필(username/display_name/organization/email)
GET/POST/api/v1/projects (선택)프로젝트 목록 / 업서트(client_id 키)
POST/api/v1/projects/{id}/conversations (선택)대화 업서트(push) — chat의 messages 스키마 재사용

모든 엔드포인트 Authorization: Bearer <JWT>. 미구현(404/501)·오프라인은 graceful fallback(프로필→OS 사용자명, 동기화→"미지원").

프로젝트/대화 · 로컬 + 동기화

로컬 우선, 선택적 push 동기화

  • ✓ IChatHistoryService → %APPDATA%/OhMyAgent/sessions/{id}.json
  • ✓ IProjectService → .../projects/{id}.json. 원자적 upsert, 동일 직렬화 옵션
  • ✓ ChatSessionRecord.ProjectId(null=미분류)로 N:1 귀속. ConversationCount는 group-by 산출
  • ✓ 동기화 키 = client_id(클라 GUID). 충돌 해소 = updated_utc last-write-wins
  • ✓ push(로컬→서버) 위주. pull은 목록 수준(타 PC 프로젝트 표시)
🗂️

도메인

Project = 대화 세션 컨테이너(작업 폴더 비포함)

사이드바: 프로젝트 그룹 + 미분류, 대화 드래그앤드롭 분류. 동기화는 사용자 트리거 시에만.
