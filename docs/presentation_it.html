루프 확장 ① · 위임과 컨텍스트

서브에이전트 · 자동 압축

🧬

task — 서브에이전트 위임

탐색성 하위 작업을 격리된 세션의 2차 루프로 넘기고 최종 텍스트만 회수 — 중간 도구 호출이 부모 컨텍스트를 오염시키지 않는다.
• 허용 도구 13개 화이트리스트(위험도 필터가 아니라 명시 목록)
• 깊이 1 구조적 보장 — 서브 레지스트리에 task 자체가 없어 재귀 불가
• manage_todos·screenshot·clipboard_read 제외(부모 상태 오염·프라이버시)
• 반복 상한 12회 · 결과 20,000자 절단

🗜️

ContextCompactor — 요약 압축

매 요청 전 와이어 크기를 측정해 30만자 초과 시 발동. 버리지 않고 요약한다.
• 최근 12만자는 원문 유지, 그 앞을 2048토큰 요약으로 대체
• 절단은 user/assistant 경계에서만 — tool_use/tool_result 짝을 깨지 않는다
• 요약은 누적(직전 요약을 다시 입력)
• session.Messages 는 불변 — 디스크·서버 동기화 이력은 온전
• 실패 시 폴백: 오래된 도구 결과 본문만 치환(메시지 수·역할·id 짝 보존)

둘 다 컨텍스트 예산을 지키는 장치다 — 위임은 애초에 안 들어오게, 압축은 이미 쌓인 것을 줄인다. 사용자에게는 압축 시 시스템 알림 1줄만 노출(에러 배너 아님).

루프 확장 ② · 멀티 에이전트 A2A

에이전트 간 통신 · 레지스트리 · 토큰 브로커

헤드리스 호스트가 자기 오케스트레이터를 동일한 /api/v1/agent/chat SSE 계약으로 대칭 노출(BCL HttpListener) — 다른 에이전트는 기존 AgentApiClient를 무수정 재사용해 접속합니다.

discover_agents
→
POST /agents/{id}/token
→
ask_agent (Bearer + X-A2A-Hop)
→
수신측 로컬 검증 → 위임
🗂️

레지스트리 (서버)

register(upsert)·heartbeat(lease 45s)·discover. status는 서버 read-시 계산(online/stale/offline). 발견 = capability 태그 필터.

🔐

ES256 토큰 브로커

POST /agents/{id}/token가 대상별 단명(120s) ES256 JWT 발급. 수신측은 공개키로 로컬 검증(서버 왕복 0) — aud·exp·iss 확인.

🛡️

순환·위조 방어

X-A2A-Hop 홉 카운트(초과 508) · alg 화이트리스트(ES256만, none/HS256 거부) · 내부 tool_call 억제(이중 실행 차단).

수신 인증 모드: broker(기본) · token(공유 Bearer) · anon. Go 서버(crypto/ecdsa)가 서명, C# Host가 BCL ECDsa만으로 검증 — 실서버 대상 E2E 통과(언어 간 암호 상호운용).

보안 모델 ② · 서버 제어형 도구·보안

2중 안전 — 클라 디폴트 ∪ 서버

최종 적용값 = 클라 내장 디폴트(바닥) ∪ 서버 값(추가 제약). 서버는 더 조일 수만 있고, 미구현/오프라인이면 디폴트만으로 정상 동작(graceful).

🧰

도구 노출·실행 통제

GET /api/v1/tools/policy(cached/realtime). 비활성 도구는 모델에 노출조차 안 됨 + 실행 차단.
노출/허용 = 내장 ∩ enabled − disabled. realtime은 POST /tools/authorize로 매 호출 인가(응답 없으면 fail-closed).

🚫

위험 명령 차단

SecurityValidator = 클라 내장 블랙리스트 ∪ GET /security/command-policy 추가 패턴.
서버는 추가만(디폴트 제거 불가). 정규식은 컴파일 검증 + 매치 타임아웃으로 ReDoS 방어, substring 타입 지원.

서버 값은 로그인 시 1회 로드·세션 캐시(도구 정책과 동일 라이프사이클) — 변경은 재로그인 반영.

보안 모델 ③ · 멀티루트 샌드박스

최대 10개 루트 OR 검증

IWorkspaceContext가 모든 파일/셸 경로를 활성 루트 기준으로 검증.

  • ✓ 최대 10개 루트 동시 등록 + 폴더별 Enabled 토글(전역 설정, 프로젝트 비귀속)
  • ✓ ResolvePath: 상대→주 루트 Combine, 검증은 활성 루트 OR(하나라도 내부면 통과)
  • ✓ 심볼릭/실경로(RealPath) 정규화 후 비교로 ..·절대경로·정션 탈출 차단
  • ✓ 비활성(토글 off) 루트는 샌드박스 통과 불가. run_command cwd = 주 루트

보안 모델 ④ · 데이터 주권

아웃바운드는 사내 서버 한 곳

"AI API 를 부르면 내부 정보가 국외로 나가지 않나" — 클라이언트에는 그 경로가 구조적으로 없습니다.

  • ✓ 모든 요청은 ServerBaseUrl 기준 절대 URI 로 매 호출 생성(AgentApiClient.Url()·ChatApiClient.Url()). WS 도 동일 주소에서 스킴만 http→ws
  • ✓ 버전 점검조차 사내 서버(/api/v1/client/version) — 외부 릴리스 피드·자동 다운로더 없음
  • ✓ 벤더 API 키 부재 — 저장 자격증명은 사내 JWT 하나뿐(DPAPI 암호화, [JsonIgnore] + 평문 폴백 없음)
  • ✓ provider-agnostic — 모델은 불투명 문자열 ModelId 로만 전달(AgentRequest.Model). 벤더 분기 코드 ✕, provider_type 은 역직렬화만 되고 미사용
🌏

⚠️

유일한 예외 · http_fetch

모델 지정 임의 호스트로 나가는 유일한 통로. 전용 HttpClient 분리 + UrlGuard(스킴 허용목록·DNS 해석 후 loopback/링크로컬169.254/16/멀티캐스트 차단·리다이렉트 홉마다 재검증). 사내망 RFC1918 은 의도적 허용.
완전 차단이 필요하면 서버 도구 정책에서 비활성화 → 모델에 노출조차 안 됨.

경계선: 클라이언트가 국외 반출을 강제하는 게 아니라, 벤더로 나가는 경로를 갖지 않아 서버 배포 구성만으로 결정 가능해진다. 실제 보장은 Provider 엔드포인트 리전 + 사내망 egress 정책으로 완성.

⚡

토큰 배치 플러시

50ms 또는 1,024자 중 먼저 도달하는 쪽에서 일괄 반영. 토큰마다 디스패치하면 UI 스레드 폭주 + 텍스트 증가에 따른 O(n²) 재레이아웃이 발생했다. 비텍스트 이벤트는 선(先) 플러시로 순서 보존, finally 재플러시로 취소 시 잔여 유실 방지.

⛓️

병렬 도구 실행

배치가 2건 이상이고 전부 ReadOnly 일 때만 SemaphoreSlim(8) 로 동시 실행. 결과는 완료 순으로 UI 에 흘리되 이력에는 모델의 원래 호출 순서로 기록 — tool_call_id 짝과 프롬프트 캐시 안정성 유지. 승인 대화상자가 겹칠 일이 없다.
