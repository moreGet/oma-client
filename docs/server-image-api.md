# 서버 API 요구 스펙 — 이미지 생성 (`generate_image` 도구용)

대상: 서버(API) 팀. 클라이언트 `generate_image` 도구가 호출할 **신규 엔드포인트 1개**를 요구합니다.
현재 상태: **서버에 이미지 엔드포인트가 없습니다.** 클라이언트 측 도구는 이 문서의 계약에 맞춰 **선구현 완료** — 서버가 올리면 바로 동작합니다.

> 이 문서는 **그대로 구현 프롬프트로 사용**할 수 있게 작성했습니다. 서버 저장소에서 작업하는 사람(또는 코딩 에이전트)에게 이 파일을 그대로 전달하면 됩니다. §9 수용 기준을 통과하면 완료입니다.
>
> 관련 문서: 전송 형식 전반 `docs/API_CONTRACT.md` · 도구 정책 게이트 `docs/server-tool-policy-api.md` · 쿼터 `docs/server-quota-api.md` · 압축 `docs/server-compression-spec.md`

---

## 1. 요약 — 서버가 해줘야 할 것

| # | 항목 | 담당 | 필수 |
|---|------|------|:---:|
| **1** | `POST /api/v1/images/generations` 신설 — 이미지 모델 대리 호출 | **API 앱** | ✅ |
| 2 | 에러 응답을 기존 envelope 형식으로 통일 (§4) | API 앱 | ✅ |
| 3 | 쿼터 집계에 이미지 생성 포함 (§5) | API 앱 | ✅ |
| 4 | `GET /api/v1/tools/policy` 의 도구 목록에 `generate_image` 반영 (§6) | API 앱 | ✅ |
| 5 | 프롬프트·이미지 로깅 정책 결정 (§7) | 보안/운영 | ✅ |
| 6 | nginx 요청 본문·응답 크기 상한 확인 (§7) | 인프라 | ⛔ 권장 |

**클라이언트는 이 엔드포인트가 없어도 깨지지 않습니다.** 404 를 받으면 도구가 "서버에 이미지 생성 엔드포인트가 없습니다 — 관리자에게 문의하세요. 재시도해도 동일합니다." 로 실패하고 대화는 계속됩니다. 다만 사용자에게 기능이 없는 것과 같으므로, 이 엔드포인트가 곧 이 기능의 전부입니다.

## 2. 배경 — 왜 서버가 대리 호출해야 하는가

이 제품의 데이터 주권 원칙은 **"앱은 외부 AI 회사에 직접 접속하지 않는다"** 입니다. 앱에는 외부 AI 서비스의 **API 키가 아예 없습니다** — 노트북을 분실해도 외부로 데이터를 보낼 수단이 없어야 하기 때문입니다.

따라서 이미지 생성도 채팅과 **완전히 동일한 구조**를 따릅니다.

```
[데스크톱 앱] ──HTTPS──> [사내 API 서버] ──> [이미지 모델(국내 리전 / 온프레미스)]
                              ↑
                    키 보관·모델 선택·쿼터·정책이 전부 여기
```

- 어떤 이미지 모델을 쓸지는 **회사가 서버 설정으로 결정**합니다. 모델을 바꿔도 **클라이언트는 수정하지 않습니다**.
- 클라이언트는 모델 이름조차 보내지 않습니다(§3 참조) — 채팅은 `model` 을 보내지만 이미지는 서버가 고르게 두는 편이 낫다고 판단했습니다. 클라이언트에 이미지 모델 ID 를 노출할 이유가 없고, 노출하면 사용자가 임의 모델을 지목할 수 있게 됩니다. **서버가 이견이 있으면 알려주세요** — 이 부분은 조정 가능합니다.

## 3. `POST /api/v1/images/generations`

### 요청

```http
POST /api/v1/images/generations HTTP/1.1
Content-Type: application/json
Authorization: Bearer <JWT>

{
  "prompt": "월별 매출 추이를 보여주는 심플한 라인 차트, 파란색 계열, 배경 흰색",
  "size": "1024x1024",
  "count": 1,
  "format": "png"
}
```

| 필드 | 타입 | 필수 | 설명 |
|------|------|:---:|------|
| `prompt` | string | ✅ | 생성 지시문. 한국어 포함 UTF-8. 클라이언트가 빈 값·공백만인 경우를 먼저 거부하므로 서버에 도달하지 않지만, 서버도 방어할 것 |
| `size` | string | ⛔ | `"<너비>x<높이>"`. 생략 시 서버 기본값. **모델이 지원하지 않는 값이면 400** (§4) |
| `count` | int | ⛔ | 생성 장수. 생략 시 1. 클라이언트가 상한을 걸지만 **서버도 상한을 강제할 것**(쿼터 폭주 방지) |
| `format` | string | ⛔ | `"png"`. 현재 클라이언트는 PNG 만 저장하며 **응답 바이트의 PNG 매직바이트(`89 50 4E 47`)를 검증**합니다. 다른 포맷을 넣으려면 사전 협의 필요 |

**압축**: 이 엔드포인트는 비스트리밍 REST 이므로 클라이언트의 **컨트롤플레인 클라이언트**를 타며 `Accept-Encoding` 을 보냅니다. 응답 gzip 은 켜져 있으면 그대로 이득이고, 없으면 무시됩니다(`docs/server-compression-spec.md` §2). 요청 본문 gzip 은 이 엔드포인트에서는 의미가 없습니다(프롬프트가 작음).

### 응답 200

```json
{
  "images": [
    { "b64": "iVBORw0KGgoAAAANSUhEUg...", "revised_prompt": "A simple line chart showing..." }
  ],
  "usage": { "images": 1 }
}
```

| 필드 | 타입 | 필수 | 설명 |
|------|------|:---:|------|
| `images` | array | ✅ | **비어 있으면 안 됩니다.** 빈 배열은 클라이언트가 실패로 처리합니다 |
| `images[].b64` | string | ✅ | 이미지 바이트의 base64. **데이터 URI 접두(`data:image/png;base64,`)를 붙이지 마세요** — 순수 base64 만 |
| `images[].revised_prompt` | string\|null | ⛔ | 모델이 프롬프트를 다시 쓴 경우 그 내용. 클라이언트가 도구 결과로 모델에 전달해, 모델이 결과와 의도의 차이를 알 수 있게 합니다 |
| `usage` | object\|null | ⛔ | 집계용. 클라이언트는 사용하지 않으나 서버 로깅·쿼터에 유용 |

**URL 방식은 쓰지 않습니다.** 이미지를 서버에 저장하고 URL 을 돌려주는 방식은 채택하지 않았습니다 — ① 폐쇄망에서 이미지 보관·수명 관리가 또 하나의 운영 부담이 되고 ② 클라이언트는 결국 워크스페이스 파일로 저장하므로 한 번 더 받아오는 왕복이 낭비입니다. **base64 인라인으로 주세요.**

### 클라이언트가 응답을 받은 뒤 하는 일 (참고)

1. base64 디코드 → **PNG 매직바이트 검증** (아니면 실패)
2. **워크스페이스 안에** 파일로 저장(샌드박스 경로 검증, 경로 탈출 차단, 기존 파일 조용히 덮어쓰지 않음)
3. 모델에는 **base64 를 돌려주지 않고** `{ "path", "bytes", "size", "revised_prompt" }` 만 전달
   — 이미지 1장을 컨텍스트에 넣으면 수천~만 토큰을 먹어 긴 세션의 컴팩션을 말립니다.
4. 이 도구는 **위험도 `Write`** 로, 권한 모드에 따라 실행 전 **승인 카드**가 뜹니다("이미지 파일 생성").

## 4. 에러 계약 (기존 envelope 재사용 — 새 형식 만들지 마세요)

`docs/API_CONTRACT.md` 와 동일한 형식입니다.

```json
{ "error": { "code": "bad_request", "message": "사람이 읽을 메시지" } }
```

| 상태 | `code` | 언제 | 클라이언트 동작 |
|---:|------|------|------|
| 400 | `bad_request` | 프롬프트 누락·`size` 미지원·`count` 상한 초과 | 실패 + 고정 문구("요청에 문제가 있어 처리하지 못했습니다"). **`message` 원문은 모델·사용자에게 전달되지 않습니다**(아래 주의) |
| 401 | `unauthorized` | 토큰 만료·무효 | 도구 실패 안내만 — `"이미지 생성 실패: 로그인이 만료되었습니다. 다시 로그인한 뒤 시도해 주세요."` **로그아웃은 하지 않습니다.** 이 엔드포인트는 스트리밍 채팅 경로가 아니라 도구 경로라, 401 을 재로그인으로 승격시키는 장치(`ClassifyAgentError`)를 지나지 않습니다 |
| 403 | `forbidden` | 도구 정책·권한으로 차단 | 실패 안내만(로그아웃 없음) |
| 429 | `rate_limited` | 쿼터 초과 | 실패 안내만. `message` 에 `daily`/`weekly`/`monthly` 중 하나가 들어 있으면 클라이언트가 기간을 문구에 반영합니다(그 밖의 자유 문장은 쓰이지 않습니다) |
| 5xx | `backend_error` | 이미지 모델 호출 실패 | 실패 안내만 |
| 404 | — | **엔드포인트 미구현** | "서버에 이미지 생성 엔드포인트가 없습니다 — 관리자에게 문의하세요. 재시도해도 동일합니다." |

**주의 — `message` 원문은 클라이언트를 통과하지 않습니다.** 이 앱은 기존 관례대로 서버 오류 문구를 사용자·모델에게 그대로 보여 주지 않고, **상태코드/`code` 기준으로 한국어 문구를 만들어** 씁니다(`UserErrorMessages.ForAgentError`). 따라서:

- **판별 가능한 신호는 상태코드와 `code` 뿐입니다.** 실패 원인을 구분해야 한다면 `code` 를 나눠 주세요(자유 문장에 담으면 사라집니다).
- `message` 는 **서버 로그·운영 진단용**으로만 의미가 있습니다. 사람이 읽는 상세 설명을 공들여 쓸 필요는 없습니다.
- 예외는 429 뿐입니다 — `message` 안의 `daily`/`weekly`/`monthly` 키워드만 기간 표시에 쓰입니다.

**중요 — 실패를 5xx 로 뭉개지 마세요.** 쿼터 초과를 500 으로 내리면 클라이언트가 일시 장애로 오해합니다. 특히 **인증 실패를 5xx 로 내리면 헤드리스 호스트가 무한 재시도에 빠집니다**(`docs/server-service-account-api.md` 에 같은 요구가 있습니다).

**타임아웃 — 클라이언트 상한은 요청당 180초입니다.** 이미지 생성은 채팅보다 오래 걸리므로 이 엔드포인트만 컨트롤플레인 기본값(30초)에서 올려 두었습니다. **180초 안에 응답해 주세요** — 그보다 오래 걸리면 클라이언트가 연결 실패로 처리하고, 그때 서버에서 생성이 성공했더라도 결과는 버려지며 쿼터는 이미 소모된 상태가 됩니다. 서버·nginx 의 상한도 모델 실제 소요보다 넉넉히 잡아 주세요(게이트웨이가 먼저 끊으면 클라이언트에는 원인 불명의 절단으로 보입니다 — 실제로 채팅 SSE 에서 `The response ended prematurely` 를 겪은 적이 있습니다).

**응답 본문 상한 — 32MB.** base64 응답은 본문 크기가 곧 클라이언트 힙 사용량이라 상한을 둡니다. `Content-Length` 를 주면 초과 시 본문을 읽지도 않고 거부하고, chunked 응답은 읽는 도중 상한에서 중단합니다. 개별 이미지도 디코드 후 16MB 를 넘으면 저장하지 않습니다. `count` 상한 4와 함께 보면 정상 응답은 이 안에 들어오지만, **한 장이 매우 큰 해상도로 오면 걸릴 수 있습니다**(그 경우 클라이언트는 "size 나 count 를 줄이세요"로 실패합니다).

## 5. 쿼터 연동

- 이미지 생성은 토큰 과금 체계와 단위가 다릅니다(장수 기준). **`GET /api/v1/me/quota` 집계에 어떻게 반영할지 서버가 정해 주세요.**
- 최소 요구: **쿼터를 초과하면 429 + `rate_limited`**. 클라이언트는 이미 429 를 "메시지만 표시, 로그아웃 없음" 으로 처리합니다.
- 권장: 이미지 생성에 **별도 한도**를 두세요. 텍스트 쿼터와 한 통에 넣으면 이미지 몇 장이 하루 대화 예산을 태울 수 있습니다.
- `count` 상한을 서버가 강제해야 합니다. 클라이언트 상한만으로는 방어가 되지 않습니다(클라이언트는 신뢰 경계 밖입니다).

## 6. 도구 정책 연동

`generate_image` 는 서버가 켜고 끌 수 있어야 합니다. `GET /api/v1/tools/policy` 의 `enabled`/`disabled` 목록에서 **`generate_image`** 라는 이름으로 다뤄 주세요(`docs/server-tool-policy-api.md`).

- 정책으로 차단하면 클라이언트는 **모델에게 이 도구를 아예 노출하지 않습니다** — 모델이 존재를 모르므로 호출 시도조차 없습니다.
- `realtime` 모드라면 `POST /api/v1/tools/authorize` 에 `{ "tool": "generate_image", "arguments": { "prompt": "..." } }` 가 올라옵니다. **프롬프트 내용으로 정책 판단이 가능**합니다(부적절 요청 차단 등).
- 서버가 정책으로 차단하는 것과 엔드포인트가 403 을 주는 것은 **둘 다 필요합니다** — 정책은 모델 노출을 막고, 403 은 우회 호출을 막습니다.

전체 도구 목록은 `docs/server-tool-policy-api.md` 의 도구 인벤토리 표를 보세요.

## 7. 보안·운영 요구

| 항목 | 요구 |
|------|------|
| **프롬프트 로깅** | 프롬프트에 사내 정보가 들어갑니다. 로깅 여부·보존 기간을 **명시적으로 결정**해 주세요. 기본은 "남기지 않음" 을 권합니다 |
| **생성 이미지 보관** | 서버에 이미지를 저장하지 마세요(URL 방식을 안 쓰는 이유와 동일). 응답으로 넘기고 서버에서는 버리는 것이 데이터 잔류 면에서 낫습니다 |
| **응답 크기** | base64 는 원본의 약 1.37배입니다. 1024×1024 PNG 가 수백 KB~수 MB 이므로 **nginx `client_max_body_size` 와 응답 버퍼 상한**을 확인해 주세요. 클라이언트도 자체 상한을 두어 거대한 응답으로 메모리가 터지지 않게 방어합니다 |
| **모델 선택** | 서버 설정으로만. 클라이언트가 모델을 지목할 수 없어야 합니다 |
| **데이터 주권** | 이미지 모델도 **국내 리전 또는 온프레미스**여야 합니다. 채팅 모델과 같은 기준입니다 |

## 8. 클라이언트가 실제로 의존하는 것 (계약 위반 시 깨지는 지점)

서버 구현이 아래를 어기면 **클라이언트가 조용히 또는 요란하게 깨집니다**. 변경 전 반드시 협의해 주세요.

| 클라이언트 기대 | 어기면 |
|---|---|
| `images` 가 **비어 있지 않다** | 도구가 "이미지를 받지 못했습니다" 로 실패 |
| `images[0].b64` 가 **순수 base64** (데이터 URI 접두 없음) | base64 디코드 실패 또는 PNG 매직바이트 검증 실패 |
| 디코드 결과가 **실제 PNG** | 매직바이트 검증 실패 → 손상 파일을 워크스페이스에 쓰지 않고 실패 |
| 에러가 **`{ "error": { "code", "message" } }`** 형식 | `code` 를 못 읽어 모든 실패가 "일시적인 서버 오류" 로 뭉개짐(쿼터 초과·권한 문제를 구분할 수 없게 됨) |
| 쿼터 초과가 **429** | 5xx 로 오면 일시 장애로 오해해 사용자가 재시도를 반복 |
| 인증 실패가 **401** | 5xx 로 오면 헤드리스가 무한 재시도 |

---

## 9. 수용 기준 (이걸 통과하면 완료)

- [ ] `POST /api/v1/images/generations` 가 200 + `images[0].b64`(순수 base64, PNG) 를 반환한다
- [ ] `Authorization` 헤더 없이 호출하면 **401 + `unauthorized`**
- [ ] `prompt` 를 비우면 **400 + `bad_request`** (원인 상세는 서버 로그에 남긴다 — `message` 는 클라이언트를 통과하지 않는다)
- [ ] 지원하지 않는 `size` 는 **400** (지원 목록은 서버 로그·운영 문서에 남긴다)
- [ ] `count` 상한 초과는 **400** (서버가 강제한다)
- [ ] 쿼터 초과는 **429 + `rate_limited`** (5xx 아님)
- [ ] 이미지 모델 장애는 **5xx + `backend_error`**
- [ ] 응답에 **데이터 URI 접두가 붙지 않는다**
- [ ] `GET /api/v1/tools/policy` 의 `disabled` 에 `generate_image` 를 넣으면 클라이언트가 도구를 모델에 노출하지 않는다
- [ ] `realtime` 모드에서 `POST /api/v1/tools/authorize` 에 `tool: "generate_image"` 가 도달한다
- [ ] 이미지 생성 소요가 게이트웨이 타임아웃보다 짧다(또는 타임아웃을 늘렸다)
- [ ] 프롬프트 로깅 정책이 문서화됐다

### 확인용 curl

```bash
# 정상
curl -sS -X POST "$BASE/api/v1/images/generations" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"prompt":"파란색 계열의 심플한 라인 차트","size":"1024x1024","count":1,"format":"png"}' \
  | python3 -c 'import json,sys,base64; d=json.load(sys.stdin); b=base64.b64decode(d["images"][0]["b64"]); print("PNG" if b[:4]==b"\x89PNG" else "NOT PNG", len(b), "bytes")'

# 인증 없음 → 401 unauthorized
curl -sS -o /dev/null -w '%{http_code}\n' -X POST "$BASE/api/v1/images/generations" \
  -H 'Content-Type: application/json' -d '{"prompt":"x"}'

# 빈 프롬프트 → 400 bad_request
curl -sS -X POST "$BASE/api/v1/images/generations" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"prompt":"   "}'
```

## 10. 클라이언트 측 구현 상태

- 도구명 **`generate_image`**, 위험도 **`Write`**(승인 카드 대상)
- 비스트리밍 REST 경로(컨트롤플레인 클라이언트)로 호출 — 응답 gzip 수용
- 결과를 **워크스페이스 안 PNG 파일**로 저장(샌드박스 경로 검증, 경로 탈출 차단, 조용한 덮어쓰기 없음)
- 모델에는 `{ path, bytes, size, revised_prompt }` 만 반환 — base64 는 컨텍스트에 넣지 않음
- 404 는 **"엔드포인트 미구현"** 으로 명확히 안내(모델이 재시도로 턴을 낭비하지 않게)
- **서브에이전트(`task` 도구)에는 노출하지 않음** — 위임 작업이 쿼터를 태우는 것을 막기 위해 허용목록에서 제외하고 테스트로 잠갔습니다

서버가 올라가면 클라이언트 수정 없이 동작합니다. 엔드포인트 배포 후 알려주시면 실기 검증하겠습니다.
